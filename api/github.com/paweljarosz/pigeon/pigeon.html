paweljarosz/pigeon

Easily and safely manage posting messages in Defold.

  • GitHub: paweljarosz/pigeon — pinned to v1.5
    1. Pick a release from paweljarosz/pigeon releases and add its Source code (zip) URL (or a packaged .zip asset, if the library ships one) to game.project under [project] dependencies, then Fetch Libraries in the Defold editor.
    2. Run bunx @defold-typescript/cli resolve to materialize its types.
    3. Import it under a namespace alias of your choice:

define(message_id: MessageId, message_def?: MessageDefinition): boolean

Define a single message schema for runtime validation. Built-in Defold/system message ids are always protected from redefinition.

Parameters

  • message_id: MessageId — @Defold message_id string or hashed.
  • message_def?: MessageDefinition — @Optional message definition table.

Returns

  • boolean — @True if defined successfully, false otherwise.

define_batch(letters_table: LuaMap<string, LetterEntry> | Record<string, LetterEntry>, is_overwriting?: boolean): LuaTable<string, boolean>

Define multiple message schemas at once from a table of letter definitions. Built-in Defold/system message ids are always protected from redefinition.

Parameters

  • letters_table: LuaMap<string, LetterEntry> | Record<string, LetterEntry> — @Table mapping keys to {id = MessageId, data = MessageDefinition}.
  • is_overwriting?: boolean — @If true, allows overwriting existing user-defined definitions.

Returns

  • LuaTable<string, boolean> — @Per-key result map.

subscribe(messages: MessagesGroup, callback?: (...args: any[]) => unknown, url?: Url | Opaque<"userdata"> | string, context?: LuaTable, is_optimizing?: boolean): number | boolean

Subscribe to given message_id(s) and optionally add a hook called immediately on send. Hook runs synchronously in the sender context (inside Pigeon.send) before msg.post, and does not run in the receiver script.

Parameters

  • messages: MessagesGroup — @Table containing message_id(s) that caller will be subscribed to. Can be a single message as string or hash or a table containing messages as strings or hashes.
  • callback?: (...args: any[]) => unknown — @Optional callback function to be called everytime, when sending subscribed message(s). Uses context parameter.
  • url?: Url | Opaque<"userdata"> | string — @Optional URL of the subscriber (v1.3 order).
  • context?: LuaTable — @Optional context to be passed to the callback function.
  • is_optimizing?: boolean — @If true, skips subscribing to messages already registered for the same url.

Returns

  • number | boolean — @Unique id of the subscription if subscribed succesfully, false otherwise.

extend_subscription(id: number, messages: MessagesGroup): boolean

Add message subscriptions to an existing subscriber id.

Parameters

Returns

  • boolean — @True if updated successfully, false otherwise.

Remove message subscriptions from an existing subscriber id.

Parameters

  • id: number — @Id of the subscriber to update.
  • messages: MessagesGroup — @Table containing message_id(s) to remove.

Returns

unsubscribe(id?: number | number[] | boolean | undefined): boolean

Unsubscribe one or more subscriptions.

Parameters

  • id?: number | number[] | boolean | undefined — @Single subscriber id, or a table of subscriber ids. If false or nil it will do nothing and will return false.

Returns

  • boolean — @True if all unsubscribed succesfully, false otherwise.

unsubscribe_all(): boolean

Unsubscribe all saved subscriptions.

Returns

  • boolean — @True if unsubscribed all succesfully, false otherwise.

Send a message of given message_id with given message table to all subscribed subscribers. Additionally, Pigeon checks in runtime if message is correct if defined. If the message has a hook attached, it will be called immediately.

Parameters

  • message_id: MessageId — @Defold message_id string or hashed. It will be prehashed anyway.
  • message?: LuaTable — @Optional definition message table to check before sending.

Returns

  • boolean — @True if data is correct and send succesfully, false otherwise.

send_to(url: Url | string | hash | Opaque<"userdata">, message_id: MessageId, message?: LuaTable): boolean

Equivalent to Defold built-in msg.post. Sends a message of given message_id with an optional data in message table to a specified url. Accepts the same target forms as msg.post: a url userdata, a url-like string (e.g. "/gui#hud" or "#fragment"), or a hash game object id (e.g. the id returned by factory.create or go.get_id). Additionally, Pigeon checks in runtime if message is correct if defined.

Parameters

  • url: Url | string | hash | Opaque<"userdata"> — @Target's url, url-like string, or game object hash id.
  • message_id: MessageId — @Defold message_id string or hashed. It will be prehashed anyway.
  • message?: LuaTable — @Optional message table to check.

Returns

  • boolean — @True if data is correct and send succesfully, false otherwise.

toggle_logging(enable: boolean)

Enable or disable logging functionality. It only switches between default logging (printing to console) and not logging. If you want to use dependency logging, you need to set dependency again after enabling logging. The correctness of arguments is not checked! Use responsibly!

Parameters

  • enable: boolean — @Flag to set logging enabled (true) or disabled (false).
